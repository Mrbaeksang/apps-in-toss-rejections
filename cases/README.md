새 사례를 보태 주시면 큰 도움이 돼요. [CONTRIBUTING.md](../CONTRIBUTING.md)의 형식을 따라 주세요.

## R-001 다른 결제 SDK가 번들에 들어 있음

**반려 문구**

> 번들에 다른 결제 SDK(portone.io)가 들어 있어요. 미니앱에서는 토스페이와 인앱 결제만 쓸 수 있어서, 이 SDK를 뺀 뒤 다시 올려주세요.

**특징**: 검토 요청을 누르고 1초 만에 반려됐어요. 사람이 아니라 번들 문자열 검사로 보여요. **실행되지 않는 코드여도 문자열이 번들에 있으면 걸려요.**

**원인**: 같은 웹 코드를 브라우저·안드로이드 WebView·앱인토스 세 곳에서 쓰는데, 앱인토스 진입점이 브라우저용 연결 모듈을 재사용했어요. 그 모듈이 브라우저 전용 PG(PortOne) 결제 코드와 Google Ad Manager 광고 코드를 import하고 있었어요. 토스 화면에서는 닿지 않는 코드였지만 번들에는 `https://cdn.portone.io/...` 문자열이 그대로 들어갔어요.

**고친 방법**

1. 브라우저 전용 결제·광고 모듈을 공용 모듈에서 떼어, 브라우저 진입점에서만 주입했어요(의존성 주입). 토스 진입점은 자기 결제(IAP)·광고만 넣어요.
2. 이미 쓰지 않던 결제 코드는 지웠어요.
3. 다시 빌드한 뒤 `node scripts/scan.mjs dist`로 결제·광고·로그인 SDK 문자열이 0건인지 확인하고 올렸어요.

**미리 막는 법**: 빌드 산출물을 검사하세요. 소스 grep은 트리 셰이킹 결과를 모르니 **산출물**을 봐야 해요.

## R-002 서비스 설명 없이 즉시 토스 로그인을 유도

**반려 문구**

> 서비스 설명 없이 즉시 토스 로그인을 유도하고 있어 인트로 페이지 추가가 필요해요. 서비스를 소개하는 인트로 페이지가 먼저 노출된 후 토스 로그인이 진행될 수 있도록 수정해 주세요.

**원인**: 로그인하지 않은 사용자의 첫 화면이 "로그인하면 볼 수 있어요" 잠금 카드와 로그인 버튼이었어요. 로그인 시트를 자동으로 띄우지는 않았지만, 무슨 서비스인지 설명하는 화면이 없었어요.

**고친 방법**: 로그인하지 않은 사람이 처음 들어오면 인트로 화면을 먼저 보여 줘요.

- 서비스 이름, 한 줄 소개, 주요 기능 3가지
- 주 버튼 "토스로 시작하기" → 토스 로그인
- 보조 버튼 "먼저 둘러보기" → 로그인 없이 둘러보기

로그인한 사람에게는 보여 주지 않아요. 진입하자마자 바텀시트로 로그인을 띄우는 것은 별도 항목(진입 시 바텀시트 금지)에도 걸리니 하지 마세요.
